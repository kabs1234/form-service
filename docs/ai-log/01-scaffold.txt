● Short answer: not for the function Express calls directly. Express calls
  middleware as fn(request, response, next), three separate arguments, and we
  can't change that.

  Express also looks at how many parameters a function declares (fn.length). A
  middleware with 4 parameters is treated as an error handler. So the parameter
  list of a middleware isn't just a style choice; Express reads it.

  So sendSpaIndex has to keep the (request, response, next) shape when it's
  passed to app.use. There are two honest options:

  A. Keep the Express signature (recommended). This is the "deliberate
  exception" case the skill allows: the framework dictates the signature, not
  us. Every Express codebase and every tutorial uses this shape, so it's also
  the easiest to explain in an interview.

  B. Use an options object and adapt it at the call site.
  type SpaFallbackContext = {
    readonly request: Request
    readonly response: Response
    readonly next: NextFunction
  }

  function sendSpaIndex({ request, response, next }: SpaFallbackContext): void {
  ... }

  app.use((request, response, next) => sendSpaIndex({ request, response, next
  }))
  This meets the 2-argument rule, but the adapter is an extra layer. Every route
  in step 4 would need the same wrapper, and the code would look unusual to
  anyone who knows Express.

  I'd go with A and treat framework callbacks (Express middleware and route
  handlers) as the one exception to the 2-argument rule. Which do you prefer?
  I'll write server/index.ts once you decide.
