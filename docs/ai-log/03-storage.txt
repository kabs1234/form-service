  How it works, part by part:

  - Data lives in memory. On startup, loadStorage() creates data/ if it's
    missing and reads db.json into the database variable. If the file doesn't
    exist yet, it starts empty. All reads (listForms, findFormBySlug, …) come
    from memory, so they're instant.
  - The file is checked on load. The contents are validated with databaseSchema,
    which is built from the /shared schemas. If the file is broken, the server
    refuses to start rather than overwriting it with an empty database and
    losing data.
  - Changes never edit in place. saveForm and addResponse build a new object ({
    ...database, forms: … }) and swap it in. Each disk write saves one complete,
    consistent snapshot.
  - One write at a time (persistDatabase). writeQueue is a chain of promises.
    Each new write is attached with .then, so it starts only after the previous
    one finishes. Without this, two submissions arriving together could write
    the file at the same time and one would be lost.
    - The caller gets the write's own promise, so the API can send 201 only
      after the data is on disk. If a write fails, the caller sees that error.
    - The stored queue gets .catch(continueAfterFailedWrite). One failed write
      doesn't block every later write.
  - Safe file replacement (writeDatabaseFile). It writes the data to
    db.json.tmp, then renames that file over db.json. A rename replaces the file
    in one step, so a crash mid-write leaves the old db.json intact instead of
    a half-written one.
  - Analytics events go in a separate file. appendEvent adds one JSON line to
    events.jsonl and never rewrites the file. Events are frequent and never
    change, so they skip the database write queue entirely. listEvents reads the
    file and drops lines that don't parse, such as a line cut off by a crash.
