  New dependency: react-hook-form (it's in the CLAUDE.md stack, and supports

  Instead, answers-resolver.ts (src/lib/answers-resolver.ts) is about 20 lines

  exactly the same zod schema.

  How it fits together:
  - public-form-page.tsx (src/pages/public-form-page.tsx) loads the form and
    shows one of four things: loading, the friendly 404, a load error, or the
    form. After a successful submit it shows the thank-you screen.
  - public-form.tsx (src/components/public-form/public-form.tsx) holds the
    react-hook-form setup. Each question uses the same FormField component as
    the builder's live preview. If the server rejects a submit, its message
    appears above the Submit button.
  - answers-draft.ts (src/lib/answers-draft.ts) reads, saves and clears the
    draft in localStorage under the key form-draft:<slug>. Because the manager
    can edit the form after a student started, the restore step:
    - checks the saved draft with zod;
    - drops answers for deleted questions;
    - drops choices that are no longer options.
  - If localStorage is unavailable (private mode or full storage), saving fails
    quietly and the form still works.
  - use-draft-autosave.ts (src/hooks/use-draft-autosave.ts) saves the draft
    whenever an answer changes. It uses react-hook-form's subscribe, which runs
    only on value changes, so the page doesn't re-render on every keystroke.
    That also means a late save can't bring the draft back after a successful
    submit.
  - I moved the form title and description into a shared form-heading.tsx
