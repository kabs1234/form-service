> Can we maybe just insert it rather than clearing?

● Yes, inserting is the right idea. The catch is where we insert.

  - Into the files directly: this only works while the server is stopped. The
    server loads db.json into memory at startup and rewrites the whole file on
    every save. If a script added demo responses to db.json while the app was
    running, the next save (say, a student submitting) would overwrite them, and
    they'd silently disappear. Events would survive, since events.jsonl is
    append-only and re-read on each request. So we'd still need "stop the server
    first", which is the same ordering problem with a different shape.
  - Through the running server's API: the server adds the records to memory and
    saves them through its normal write queue. Nothing gets cleared or
    overwritten, it works at any time, and running it twice just adds more. This
    is what the simulator does.

  So the simulator is the "just insert it" version, and the only one that's safe
  while the app runs. It would add a separate demo form with its responses and
  visits next to whatever is already there, and leave your existing forms and
  data untouched.
